# Project Environment

- Native Open/Save panels activate `com.apple.finder` chord scope before the real app and global scopes. `app/frontmost/file_picker/native.rs` owns Rust AX/NSWorkspace observers with no polling timer; `file_picker.rs` follows Accessibility permission changes and publishes cached `frontmost.filePickerActive`. Keep the actual app ID for handler context. The chord panel mirrors Finder priority. Main-thread Rust fixture: `cargo run --manifest-path apps/chord-tauri/src-tauri/Cargo.toml --example file-picker -- --ui`; scope coverage: `cargo test --lib file_picker_tests`. All handwritten C/Objective-C and the `cc` build dependency have been removed from Chord. Raw HID input and toggle control use typed IOKit bindings in `caps_listener.rs` / `caps_lock.rs`, with atomic shutdown and RAII cleanup.

- Backslash autosuggest lives in `routes/chords/index/chord-suggestions.ts` and `chords-page.tsx`. The `chord-macros` observable supplies current definitions; incomplete escapes show numbered buffers and named macros (with raw sequence previews) before arrow-key escapes, filtering by typed prefix anywhere in the input. Complete references hide suggestions. Both sidebar and floating layouts show the same list; floating expands only while an escape is pending. Targeted regression tests include filtering, priority, live definitions, and server rendering in both layouts.

- Chord panel layouts live in the `chord-panel` observable and persist as `chordLayout` in `app-state.json`. `0ls`/`0lsl` selects the left sidebar, `0lf`/`0lfb` selects the compact floating bottom panel, and `0lv` cycles. The native nonactivating panel resizes/repositions with the layout; the React surface fits floating content and keeps the latest keys visible. `chord-input.description` comes from Rust dispatch so it follows app/global priority, macros, regex captures, and repeat/loop prefixes. Keep canonical core TOML and its distribution copy in sync.

- Macros live in `ChordSequence`; `ChordInputManager` hydrates named definitions from `named-macros.json` at startup and saves persistent updates before applying them. Named macros persist unless their name starts with an ASCII digit (0–9); numbered buffers are always temporary. All survive input resets/config reloads. Core setters are `0b<1–9><sequence>` and `0=<name>=<sequence>`. References `\1`–`\9` and `\=name=` expand recursively before repetition, matching, and handler captures. Named references always require their closing `=`, even at the end of input. Settings → Macros uses the `chord-macros` observable and shared backend mutations to add/edit/rename/delete definitions and edit buffers. Renaming across the digit-prefix boundary updates persistence. Setters save bodies verbatim. Missing/incomplete references stay pending; recursion, depth, expansion count, and output size are bounded. The 2026-10-15 environment inspection reconfirmed the Tauri/non-React-Native setup below.

- Chord reserves `0` for global meta commands defined in `../chords/@keychord/chords-chord/chords/com/leonsilicon/chord/macos.toml` using `builtin` actions. This protected core file is bootstrapped before optional sources, restored after all package overrides, and cannot be removed or deselected. Only this file can define `0` bindings or built-in actions. `build.rs` embeds it (using the checked-in copy under `apps/chord-tauri/data/chords-chord` when the sibling checkout is unavailable); development reloads read the canonical file. Keep the distribution copy in sync. The file also supplies help and the loop halt template. Leading numeric prefixes repeat input actions; `1` starts an independent loop. Loop IDs and help live in the `chord-execution` observable; input resets preserve loops, while reload/exit stop them. In-flight JS callbacks finish on halt to preserve other handlers in their package worker. `\up`, `\left`, `\down`, and `\right` parse as physical arrow keys.

- Chord is a Bun workspace monorepo with a Tauri 2 desktop app in `apps/chord-tauri`.
- The frontend is React 19, TypeScript, Vite, and Tailwind CSS 4; it is not React Native.
- Run the app from the repository root with `bun run dev`; Vite uses port 1420.
- Run the frontend build with `bun run build` and Rust tests from `apps/chord-tauri/src-tauri` with `cargo test`.
- The settings window is created in `apps/chord-tauri/src-tauri/src/app/settings/settings_ui.rs` with label `settings`.
- The settings layout lives in `packages/dev/improve/chord/routes/settings/settings-page.tsx`.
- Route adapters stay in `apps/chord-tauri/src/routes`; reusable UI belongs in workspace packages.
- The existing sidebar primitive is `@chord/dev.improve.chord.components.ui.sidebar`.
- Native macOS translucency is available through Tauri window effects; `window-vibrancy` 0.8 is also already present.

- 2026-10-12 crash investigation: reproduced NodeSwift 1.5.1's `NodeExecutor.enqueue` abort after an async `NodeActor` → `MainActor` hop with multiple addon environments. The tray and menu packages in `../chords/@keychord/` now return promises from synchronous NodeFunction entrypoints and capture an explicit NodeAsyncQueue for completion. Do not reintroduce async NodeFunction wrappers around MainActor work. Regression: `CHORD_NATIVE_TEST_HOST=<Chord executable> bun test __tests__/actor-queue.test.ts` from the tray package.
- Caps+Space activation uses `CapturedKeyEvent`'s Caps state at capture time; queued Caps events must not overwrite the newer physical HID state. Native artifact staging uses rename so rebuilds preserve images mapped by a running process.
- 2026-10-13: Fixed the same NodeSwift missing-queue abort in iPhone Mirroring using synchronous NodeFunction entrypoints, captured NodeAsyncQueue handles, and explicit promise completion. The Apple read-only actor-queue regression validates 500 value/void/error completions with multiple addons.
